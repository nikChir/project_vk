# Подробное описание решения
## Дообучение визуально-языковой модели для VQA на русском языке

---

## 1. Цель, задачи и ожидаемые результаты

**Цель:** дообучить (fine-tune) генеративную визуально-языковую модель для корректного ответа на вопросы пользователей по изображениям (Visual Question Answering) на русском языке, используя открытые датасеты организации deepvk (VK), и объективно оценить эффект дообучения по сравнению с исходной моделью.

**Задачи:**
1. Изучить открытые датасеты и модели коллекции deepvk (Vision-Language Modeling).
2. Провести разведочный анализ данных (EDA).
3. Оценить базовую модель «как есть» (baseline) до дообучения.
4. Реализовать пайплайн препроцессинга данных и конфигурацию LoRA-дообучения.
5. Обучить LoRA-адаптер на подготовленной выборке.
6. Сравнить качество ответов модели до и после дообучения на контрольной выборке.

**Ожидаемые результаты:**
- Дообученный LoRA-адаптер для модели `deepvk/llava-gemma-2b-lora`.
- Количественное (loss) и качественное (сравнение ответов) сопоставление модели до/после дообучения.
- Полностью задокументированный и воспроизводимый пайплайн, включая описание технических трудностей и их решений.

## 2. Используемые модели и данные (открытые источники VK)

### 2.1 Выбор базовой модели

Коллекция deepvk `Vision-Language Modeling` предоставляет две LLaVA-style модели:

| Модель | Языковая часть | Параметры | Способ обучения |
|---|---|---|---|
| `deepvk/llava-saiga-8b` | Saiga-8B (LLaMA3) | 8B | Полное дообучение (3–4 дня на 8×A100 80GB) |
| `deepvk/llava-gemma-2b-lora` | Gemma-2b-it | ~2.8B | LoRA |

Выбрана **`llava-gemma-2b-lora`**: значительно легче по требованиям к вычислительным ресурсам, авторы уже применяли LoRA-адаптацию (метод дообучения согласован с исходным способом получения модели), пригодна для итеративной разработки на доступном оборудовании (Kaggle GPU).

### 2.2 Используемые датасеты

- **`deepvk/LLaVA-Instruct-ru`** — основной обучающий датасет, GPT-сгенерированные инструктивные диалоги по изображениям COCO. Два типа записей: `conversation` (диалоговые, часто многоходовые реплики) и `complex_reasoning` (развёрнутые рассуждения о содержимом изображения).
- Формат записи: `{"type": ..., "conversations": [{"from": "human"/"gpt", "value": ...}], "id": ..., "image": ...}`. Поле `id` не уникально — на одно изображение может приходиться несколько диалогов.
- **Обнаруженное расхождение:** официальный README датасета утверждает соответствие train/val сплитов COCO 2014, однако фактически `train.json` ссылается на изображения **COCO train2017**, а `val.json` — на **COCO val2014**. Подтверждено проверкой путей на уровне отдельных записей.
- Изображения получены отдельно от датасетов deepvk (которые хранят только текстовые аннотации) — через официальный источник COCO, зеркалированный на Kaggle (`awsaf49/coco-2017-dataset`, `jeffaudi/coco-2014-dataset-for-yolov3`) для удобства подключения к обучающей среде.

## 4. Оценка базовой модели (baseline)

Проведён прогон `llava-gemma-2b-lora` «как есть» на 8 случайных примерах из официального val-сплита (`llava_instruct_ru_val.json`, изображения COCO val2014, `RANDOM_SEED=42`, детерминированная генерация `do_sample=False`).

**Важное техническое наблюдение:** первый прогон, выполненный локально на Apple Silicon (backend MPS, fp16), дал полностью бессвязные ответы (смесь языков, повторы токенов) — впоследствии диагностировано как известная численная нестабильность fp16 на Metal-бэкенде. Валидный baseline получен после переноса инференса на Kaggle (CUDA, bf16) — итоговые результаты ниже относятся именно к этому, корректному прогону.

| id | Вопрос | Эталонный ответ (GPT) | Ответ модели (baseline) |
|---|---|---|---|
| 296404 | Сколько жирафов изображено на фотографии? | два жирафа | На фотографии изображено два жирафа. |
| 103306 | Что можно увидеть в ванной комнате на изображении? | душ и раковину | раковину, зеркало, душевую кабину и ванну |
| 285733 | Сколько кошек изображено на фотографии? | одна кошка | На фотографии изображена одна кошка. |
| 122251 | Расположение судна в воде? | у берега | плавая по реке |
| 206838 | Особенности внешнего вида женщин на лошадях? | купальные костюмы, «красивые» | две женщины на лошадях в воде, одна с длинными волосами, другая с короткими, обе в купальниках |
| 331455 | Судно большое или маленькое? | большое | большой корабль |
| 181969 | Какой питомец изображён? | собака | маленький пёс |
| 256156 | Общественная или частная ванная? | **частная** | **общественная** ⚠️ |

**Результат:** 7 из 8 ответов корректны и содержательны, в ряде случаев детализированнее эталона. Единственная ошибка — в вопросе, требующем логического вывода по косвенным признакам («общественная/частная ванная»).

**Вывод:** базовая модель уже демонстрирует высокое качество на прямых описательных вопросах; потенциал дообучения теоретически сосредоточен на сегменте задач, требующих более сложного логического вывода.

## 5. Методология дообучения

### 5.1 Стратегия и объём данных

- **Сбалансированная выборка**: 200 `conversation` + 200 `complex_reasoning` = 400 примеров (`seed=42`).
- **Train/val split**: 320 / 80 (сбалансированно по типам).
- Из каждой многоходовой записи `conversation` используется только первая пара вопрос-ответ (упрощение для экономии времени реализации).
- Внутренний hold-out val (80 примеров из train.json) используется для мониторинга переобучения во время тренировки; официальный `val.json` — для независимой финальной оценки (модель не видит эти данные на этапе обучения вообще).

### 5.2 Препроцессинг

PyTorch `Dataset`-класс (`VQADataset`), выполняющий на лету:
- извлечение вопроса/ответа по явной проверке поля `from` (не по позиции в списке);
- сборку промпта через `tokenizer.apply_chat_template` (формат по официальному примеру инференса deepvk);
- токенизацию и маскировку `labels` (`-100` для токенов вопроса и визуальных токенов, реальные значения — только для токенов ответа); корректность проверена ручным декодированием.

Кастомная `collate_fn`: паддинг `input_ids` (`pad_token_id`), `attention_mask` (0), `labels` (`-100`); `pixel_values` объединяются без паддинга.

### 5.3 Конфигурация LoRA

```
r = 16
lora_alpha = 32
lora_dropout = 0.05
target_modules = только языковая модель (Gemma):
    q_proj, k_proj, v_proj, o_proj,
    gate_proj, up_proj, down_proj
```

Визуальный энкодер (CLIP) остаётся полностью замороженным (стандартная практика LLaVA-style дообучения). Отбор `target_modules` потребовал явной привязки к полному пути модуля (regex с якорем на `language_model`), поскольку одноимённые слои присутствуют и в визуальном энкодере, и в языковой модели — проверено программно перебором `model.named_modules()`.

**Результат обёртки в LoRA:** 19 611 648 обучаемых параметров из 2 835 718 144 общих (**0.69%**).

## 6. Технический пайплайн и решённые проблемы

| Проблема | Причина | Решение |
|---|---|---|
| `apply_chat_template` не поддерживается процессором | Chat-шаблон хранится в токенизаторе, не в процессоре | `tokenizer.apply_chat_template` по официальному примеру deepvk |
| `TypeError: patch_size = None` | Устаревший `preprocessor_config.json` не содержит полей, ожидаемых новыми версиями `transformers` | Явная передача `patch_size`, `vision_feature_select_strategy`, `num_additional_image_tokens` при загрузке процессора |
| Несовпадение числа токенов-плейсхолдеров и визуальных признаков (575 vs 576) | Известный баг подсчёта в `transformers` (issue #36002) | Эмпирический подбор `num_additional_image_tokens=1` |
| Бессвязная генерация на локальном инференсе (Apple MPS, fp16) | Численная нестабильность fp16 на Metal | Перенос инференса на Kaggle (CUDA) |
| Невозможность отката `transformers` до версии релиза модели | Несовместимость `tokenizers==0.19.1` (Rust/PyO3) с Python 3.13 | Работа с актуальной версией через точечные исправления |
| `RuntimeError: element 0 of tensors does not require grad` | Несовместимость `gradient_checkpointing` с полностью замороженной LoRA-моделью | `model.enable_input_require_grads()` после инициализации LoRA |
| `CUDA out of memory` | `DataParallel` на связке GPU T4×2 создавал доп. расход памяти при синхронизации градиентов | Одиночный GPU (P100), `per_device_train_batch_size=1` + `gradient_accumulation_steps`, `gradient_checkpointing=True` |
| Случайное попадание больших файлов в git-коммиты | `.gitignore` не покрывал реальные пути после переименования файлов | Очистка индекса (`git rm --cached`), корректировка `.gitignore` |
| Потеря чекпоинта после закрытия интерактивной Kaggle-сессии | Draft Session не сохраняет `/kaggle/working/` постоянно | Запуск через «Save & Run All» (commit) — сохраняет Output постоянно |

## 7. Результаты обучения

### 7.1 Первый прогон — 3 эпохи (400 примеров, 320 train / 80 val)

| Эпоха | Train loss (среднее) | Eval loss |
|---|---|---|
| 1 | ~1.08 | **1.028** (лучший) |
| 2 | ~0.78 | 1.076 |
| 3 | ~0.58 | 1.122 |

Train loss монотонно снижается (до 0.814 в среднем по итогу, до 0.51 на отдельных шагах), но **eval loss растёт после 1-й эпохи** — явный признак переобучения на малом объёме данных (320 примеров). На основании этого наблюдения принято решение ограничить финальное обучение **1 эпохой**.

### 7.2 Финальное обучение — 1 эпоха

Проведено повторное обучение с `num_train_epochs=1` при прочих равных гиперпараметрах. Результирующий LoRA-адаптер (`checkpoint-20`) сохранён и использован для итогового сравнения.

### 7.3 Сравнение baseline vs после дообучения

Прогон на тех же 8 примерах (проверено программной сверкой `id` с baseline), тот же режим генерации (`do_sample=False`):

| id | Baseline (до) | После обучения | Изменение |
|---|---|---|---|
| 296404 | два жирафа | два жирафа | идентично |
| 103306 | раковина, зеркало, душевая, ванна | раковина, зеркало, душевая, ванна | **идентично** |
| 285733 | одна кошка | одна кошка | **идентично** |
| 122251 | плавая по реке | двигаясь по воде | перефразировано, смысл тот же |
| 206838 | акцент на длину волос | акцент на одежду | другой акцент, не явно лучше |
| 331455 | большой корабль | большой корабль | **идентично** |
| 181969 | маленький пёс | «изображен собака» | ⚠️ потеря детали + грамматическая ошибка |
| 256156 | общественная (ошибка) | общественная (ошибка) | **ошибка не исправлена** |

### 7.4 Честный вывод

Дообученная модель **практически не отличается** от baseline на контрольной выборке: в трёх случаях из восьми ответ дословно совпадает, ключевая ошибка (частная/общественная ванная) не исправлена, в одном случае наблюдается небольшая грамматическая регрессия.

Это согласуется с количественными данными: eval loss после 1 эпохи (1.028) практически не отличается от уровня, который можно считать «точкой отсчёта» — за один проход по 320 примерам модель не успела значимо измениться. **Значимого улучшения качества на данном объёме и длительности обучения не продемонстрировано.**

## 8. Ограничения и возможные направления улучшения

1. **Малый объём обучающих данных** (320 примеров) — основная вероятная причина отсутствия значимого эффекта и быстрого переобучения. Увеличение выборки на порядок (несколько тысяч примеров) требует кратно большего времени обучения (при сохранении текущей скорости — порядка 8-10+ часов вместо ~35 минут).
2. **Отсутствие learning rate scheduler с warmup и более тонкого контроля переобучения** (early stopping по eval loss, регуляризация) — использовался линейный scheduler по умолчанию без дополнительной настройки.
3. **Упрощённая обработка многоходовых диалогов** — использовалась только первая пара вопрос-ответ из каждой записи `conversation`, что могло снизить эффективное разнообразие обучающего сигнала.
4. **Отсутствие формальной метрики** (например, через `lmms-eval` на GQA-ru/MMBench-ru) — оценка проведена на 8 примерах вручную; для статистически значимых выводов потребовалась бы оценка на существенно большей выборке.
5. Не проводился систематический формализованный качественный аудит датасета (пункт 3.3) — ограничение по времени практики.

## 9. Воспроизведение решения

1. Скачать данные: `deepvk/LLaVA-Instruct-ru` (HuggingFace), изображения COCO train2017/val2014.
2. Скачать модель: `hf download deepvk/llava-gemma-2b-lora --local-dir models/pretrained/llava-gemma-2b-lora`.
3. Запустить EDA: `notebooks/`.
4. Запустить препроцессинг + обучение: `python -m src.data_prep.dataset` (GPU обязателен, рекомендуется Kaggle с одиночным GPU, во избежание `DataParallel`-related OOM).
5. Запустить сравнение до/после: `python -m src.inference.after_training`.

Полный список решённых технических проблем — раздел 6, необходим при воспроизведении на иной версии `transformers`/иной вычислительной среде.
